## Overview

### The Strategy

This project uses **selective file tracking** to balance:

1. **Security:** API keys and secrets never committed
2. **Deployability:** All necessary files for production in git
3. **Practicality:** Large files and local configs stay local

### Key Principle

**Tracked files (▶) = Cloud deployment** | **Untracked files (⊘) = Local development**

This means:
- When you push to GitHub, only tracked files are included
- Cloudflare Pages gets exactly what's needed to deploy
- Your secrets stay on your machine
- Each developer can have their own configuration

## Why This Strategy

### Why Track app.js but Not config.local.js?

**app.js should be tracked because:**
- Application logic is not sensitive
- It's needed for deployment to work
- Developers need to collaborate on it
- It's in the public repo anyway

**config.local.js must NOT be tracked because:**
- Contains secret API keys
- Specific to each developer/environment
- Exposing it would compromise security
- Git history persists forever

### Why Keep transit-cache.json Untracked?

**Not tracking because:**
- It's 3.1 MB (slows down git operations)
- It's generated, not hand-written
- It can be regenerated anytime
- Git prefers source files, not generated outputs

**Build system instead:**
1. Developer runs: `node scripts/build-cache.js`
2. Generates transit-cache.json locally
3. If needed on cloud, add to build command
4. Or pre-generate before deployment

### Why Track config.template.js but Not config.js?

**Template is tracked because:**
- Shows developers what keys are needed
- Good reference and documentation
- No actual secrets, just comments
- Helps with setup process

**Generated config.js is not tracked because:**
- It contains actual secrets (when generated)
- It's created by build script at deployment
- Each environment has different values
- Cloudflare creates it automatically

## Common Git Operations

### Clone the Repository

```bash
git clone https://github.com/yourusername/Maps.git
cd Maps
```

**Result:**
- You get all ✓ files (app.js, index.html, src/styles/styles.css, etc.)
- You DON'T get ⊘ files (config.local.js, transit-cache.json)
- Map won't work yet (missing config.local.js)

### Set Up Local Configuration

```bash
cp src/config.template.js src/config.local.js
nano src/config.local.js  # Add your API keys
```

**Result:**
- ✓ app.js can now import from config.local.js
- Local development works
- Git won't track config.local.js (it's in .gitignore)

### Build Transit Cache

```bash
node scripts/build-cache.js
```

**Result:**
- Creates `scripts/transit-cache.json`
- ~3.1 MB file for improved performance
- git status won't show it (it's in .gitignore)

### Make Changes and Commit

```bash
# Edit some files
nano src/app.js          # Change app logic
nano src/styles/styles.css   # Change styling
nano README.md           # Update docs

# Add to staging (only changed tracked files)
git add .

# Commit
git commit -m "Add new feature: search highlighting"

# Push to GitHub
git push origin main

# Result: Only changed tracked files are pushed
# config.local.js stays local ✓
```

### Check What Would Be Committed

```bash
git status

# Output shows:
# On branch main
# nothing to commit, working tree clean
#
# (Untracked files: config.local.js, transit-cache.json, etc are NOT listed)

git ls-files
# Shows only tracked files

git ls-files --others --exclude-standard
# Shows untracked files (local only)
```

### Accidentally Modified a Tracked File?

```bash
# Oops, edited public/index.html
git diff public/index.html  # See changes
git checkout public/index.html  # Discard changes
git restore public/index.html  # Alt command (git 2.23+)
```

### Accidentally Staged a Local File?

```bash
# Oops, staged config.local.js
git status
# Shows: Changes to be committed: config.local.js

git reset config.local.js  # Remove from staging
git status
# Shows: Untracked files: config.local.js (stays local)
```

### Need to Update config.template.js?

```bash
# Template might change with new features
nano src/config.template.js

# Then make corresponding changes to local version
nano src/config.local.js

# Commit the template (not the local config)
git add src/config.template.js
git commit -m "Add new config option: FEATURE_FLAG"
git push

# Your config.local.js stays local and doesn't push
```

## Verification Commands

```bash
git ls-files
```

**Output:** All files in git (should match our tracked list)

### See Everything Untracked (Local)

```bash
git ls-files --others --exclude-standard
```

**Output:** All local files not in git

### Full Repository Status

```bash
git status
```

**Output:**
- Should show nothing to commit
- Untracked files won't be listed (excluded by .gitignore)

```bash
git ls-files --cached src/app.js
# Output: src/app.js (tracked)

git ls-files | grep config.local
```

## Troubleshooting

### Problem: git status Shows config.local.js

**Symptom:**
```
$ git status
Untracked files:
  (use "git add <file>..." to include in what will be committed)
        config.local.js
```

**Solution:**
1. File exists but .gitignore doesn't have it
2. Add to .gitignore:
   ```bash
   echo "src/config.local.js" >> .gitignore
   ```
3. Remove from git history (if already committed):
   ```bash
   git rm --cached src/config.local.js
   ```

### Problem: Accidentally Committed Secret

**Symptom:**
```
$ git log --pretty=format:"%h %s"
a1b2c3d Forgot to .gitignore config.local.js
```

**Emergency Fix:**
1. **Immediately rotate the API key:**
   ```bash
   # Go to digitransit.fi and generate new key
   # Update Cloudflare Pages environment variable
   # Update local config.local.js
   ```

2. **Remove from git history:**
   ```bash
   # Use git filter-branch or BFG Repo-Cleaner
   # This is complex, consider it a learning experience
   ```

3. **Going forward:**
   - Add pre-commit hook to catch secrets
   - Use git-secrets tool
   - Always verify commits before pushing

### Problem: app.js Can't Find config

**Symptom:**
```
Uncaught TypeError: Cannot find module './config.local.js'
```

**Solution:**
1. Verify file exists:
   ```bash
   ls src/config.local.js  # Should exist
   ```

2. Verify it's not git-ignored accidentally:
   ```bash
   git ls-files --cached src/config.local.js  # Should be empty
   git ls-files --others src/config.local.js  # Should show the file
   ```

3. Verify import path in app.js:
   ```bash
   grep "import.*config" src/app.js
   # Should show: import { ... } from './config.local.js'
   ```

4. Check for typos:
   - File: `config.local.js` (not `config_local.js`)
   - Path: `./config.local.js` (not `config.local.js`)

### Problem: .gitignore Not Working

**Symptom:**
```bash
git add .
# Commits files that should be ignored
```

**Solutions:**
1. **Check .gitignore path:**
   ```bash
   ls -la .gitignore        # Should exist in root
   ```

2. **Check syntax:**
   ```bash
   cat .gitignore           # Look for typos
   ```

3. **Clear git cache:**
   ```bash
   git rm -r --cached .
   git add .
   # Re-stages everything, respecting current .gitignore
   ```

4. **Test ignore pattern:**
   ```bash
   echo "test-ignore.txt" > test-ignore.txt
   git status               # Should NOT show it
   rm test-ignore.txt
   ```

## Best Practices

### For Development

**Do:**
✓ Regularly commit changes to tracked files
✓ Keep .gitignore updated as new files are created
✓ Test locally before pushing
✓ Rotate API keys every 3 months

**Don't:**
✗ Edit tracked files to add secrets
✗ Remove entries from .gitignore to track secrets
✗ Commit API keys "just for testing"
✗ Push to main without testing locally

### For Deployment

**Do:**
✓ Build transit cache before deployment
✓ Set environment variables in Cloudflare Parks
✓ Verify build command runs: `node scripts/build-secrets.js`
✓ Test deployed site works with new keys

**Don't:**
✗ Hardcode secrets in tracked files
✗ Use local config.local.js values in production
✗ Skip the environment variable setup
✗ Commit generated files

### For Teams

**Do:**
✓ Share config.template.js as reference
✓ Each developer maintains own config.local.js
✓ Document adding new config keys
✓ Use shared Cloudflare account for Pages

**Don't:**
✗ Share API keys via Slack or email
✗ Commit one developer's config.local.js
✗ Put instructions in comments to hardcode secrets
✗ Keep secrets in environment variable files

## Summary

| Aspect | Tracked | Untracked |
|--------|---------|-----------|
| **Security** | No secrets here | All secrets go here |
| **Deployment** | Needed for cloud | Only local development |
| **Size** | ~220 KB | 3+ MB (cache) |
| **Examples** | app.js, index.html | config.local.js, transit-cache.json |
| **Developers** | Share one copy | Each has own copy |
| **Git history** | Grows with code changes | Never in history |

**Golden Rule:** *If it contains a secret or is large/generated → .gitignore it. If it's application logic or assets → track it.*

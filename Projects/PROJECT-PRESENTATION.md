# Karamah Projects — presentation brief

Karamah Projects is a focused work-management app for organizing connected projects, turning tasks into visible progress, and giving every collaborator the right level of access.

## The story in one sentence

Create a workspace for each client, team, or area of work; place related projects inside it; then manage tasks, progress, and collaborators from one calm, structured workspace.

## Key features

### Workspaces and projects

- Create multiple workspaces for different companies, clients, teams, or initiatives.
- Group related projects inside each workspace.
- Switch between workspaces from the sidebar.
- Create a project during onboarding or add projects later from the workspace.
- Keep each workspace’s projects, members, settings, and activity together.

### Flexible project views

Projects can be understood in the view that fits the work:

- **Board:** move tasks through workflow columns such as Inbox, In Progress, Blocked, Completed, and Cancelled.
- **Backlog:** keep upcoming work visible and organized.
- **Calendar:** see work against dates and deadlines.
- **Gantt:** understand timing, dependencies, and project flow at a glance.
- **List mode:** scan tasks quickly in a compact format.

### Task management

- Task identifiers, titles, descriptions, priorities, labels, assignees, and due dates.
- Drag tasks between workflow columns.
- Comments, activity history, attachments, subtasks, task relations, and watchers.
- Completion and cancellation history so finished work remains understandable.
- Filters, search, saved views, and workspace-wide task views.

### Collaboration and permissions

Access is controlled inside Projects and is independent from Admin-panel roles.

- Workspace roles apply across the workspace by default: Viewer, Member, Admin, or Owner.
- Project-level roles override the workspace role for that project only.
- A workspace viewer can be made a project admin on one project.
- A workspace admin can be restricted to viewer access on a particular project.
- Workspace owners can create projects, manage members, edit settings, and control access.

### Internal and external collaborators

- Karamah members can sign in directly.
- External collaborators cannot sign up freely; they must follow an invitation.
- Invite people at workspace level or project level.
- Choose workspace access and different project roles in the same invitation flow.
- External collaborators are visibly distinguished in the Projects interface.
- Invitations include the access they are receiving and expire for security.

### Onboarding

- A guided flow creates the first workspace and starter project.
- Choose the workspace purpose and project name.
- Starter tasks give the team an immediate working example.
- Invite collaborators before opening the workspace.
- Finish directly inside the new project board.

### Notifications and feedback

- Clear success, failure, and update messages for important actions.
- Automatic toast dismissal keeps the interface clean.
- Activity and inbox surfaces keep changes visible without overwhelming the workspace.

## Suggested presentation narrative

1. **The problem:** work for different clients and initiatives becomes fragmented across tools.
2. **The structure:** one workspace per client or team, with connected projects underneath.
3. **The daily workflow:** create tasks, move them through the board, and see deadlines in calendar or Gantt views.
4. **The collaboration model:** workspace access is universal by default, while project-level access can override it.
5. **The trust model:** internal members sign in directly; outsiders are invited and receive only the access they were granted.
6. **The outcome:** a calm, transparent operating layer for projects and people.

## Visual direction for the presentation

- Quiet, editorial, and operational rather than flashy.
- Predominantly light or dark monochrome surfaces with restrained accents.
- Plus Jakarta Sans for interface and headline typography; Geist Mono for task identifiers and technical metadata.
- Use board columns, role overrides, and workspace-to-project hierarchy as the main diagrams.
- Show real UI detail: task cards, role selectors, invitation access, and the view switcher.
